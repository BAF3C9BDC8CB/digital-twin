# KG 搜索决策规则体系:何时必搜 / 可不搜 / 禁止搜 (2026-08-11)

- 角色: 知识图谱查询决策规则设计
- 关联: `2026-08-11-kg-auto-query-strategy.md`(三层漏斗+预算)、`2026-08-11-hermes-hook-dt-sense-injection.md`(注入方案)、`AGENTS.md`
- 要解决的问题: AGENTS.md 只有一条宽松豁免("无任何上下文才不查"), 不可执行。本设计给出 agent 可逐条判定的触发/豁免/禁止规则。

## 0. 设计原则

1. **KG 是加速器, 不是单点依赖** — 查不到就查磁盘, 记录不了就明示, 绝不因 KG 阻塞任务主流程。
2. **先感知再深入** — L0 sense 先于一切代码/目录探索; 不强求"第一个动作就是 KG", 但要求在深度探索代码之前完成。
3. **数据状态可辨识** — 每次引用 KG 数据必须能说出来源与状态(sense 三态: indexed / registered_not_indexed / unregistered; 命中 hop 距离)。
4. **禁止降级伪装** — degraded / 超时 / 空结果三分语义, 全 0 统计 ≠ 项目没代码; 降级必须显式标注 `⚠ KG degraded: [...]`, 不得假装查过。
5. **每次搜索有成本** — L1 一次 ≈1.4s / 2.2K tokens; 搜索是"按需采购"不是"例行公事", 每任务有硬预算。

## 1. 任务类型分类 → 每类搜索要求

| # | 任务类型 | 判定特征(用户消息示例) | L0 sense | L1 search_kg | L2 Cypher | 次数边界 |
|---|---|---|---|---|---|---|
| A | 配置/凭据/基础设施排查 | "user-center 连的什么库""xx 的账号密码在哪""服务部署在哪台机器" | **必查** | **必查**(核心场景) | 按需(elementId 取白名单属性) | L1≤2, L2≤2 |
| B | 部署/运维操作 | "重启 svc-xx""发布 xx""看 jcli 构建日志" | **必查** | 建议 1 次(确认操作对象实体) | 按需(服务状态/配置) | L1≤1, L2≤1 |
| C | 代码修复/功能开发 | "修 xx 的 bug""加个接口""重构模块" | **必查**(项目定位, 防改错项目) | **条件必查**: 涉跨实体引用(服务名/配置/历史决策)才查; 纯文件内逻辑不查 | 否(代码问题走代码工具) | L1≤1 |
| D | 信息询问(项目相关) | "xx 项目什么技术栈""上次为什么这么改" | **必查** | **必查**(KG 核心价值场景) | 按需 | L1≤2(主查+扩查) |
| E | 信息询问(泛知识/非项目) | "Rust 生命周期""docker 怎么用" | 否 | 否 | 否 | 0 |
| F | 纯对话/闲聊/身份 | "你好""你是谁" | 否 | 否 | 否 | 0 |
| G | 记忆写入 | "记住 xx""记一下" | 否(可省) | 否 | 否 | 0 搜索, 1 写入(dt_memorize) |
| H | 跨项目/全局对比 | "所有项目里哪些用了 nacos" | **必查**(当前项目)+ 跨 world | **必查**(--world 或按项目循环) | 按需 | L1≤2 |

**判定顺序**: 先分类, 再查信号表。分类模糊时(如 C 与 D 之间)取更严格的一侧(必查)。

## 2. 触发信号 — 命中即必搜 L1

用户消息命中以下任一组关键词/实体(且任务类型 ≠ E/F/G) → **L1 必查**:

| 信号组 | 关键词/实体(示例) | 说明 |
|---|---|---|
| 服务/基础设施 | 服务名、server、host、主机、端口、数据库、中间件、memgraph、qdrant、nacos、redis、mysql、k8s、pod、网关 | 实体级信息在 KG |
| 配置/凭据 | 配置、config、账号、密码、token、密钥、凭据、auth、域名、URL、环境名(dev/test/prod) | 敏感字段按降噪规则处理 |
| 部署/生命周期 | 部署、发布、上线、回滚、重启、构建、jenkins、jcli、版本、升级 | 对应 :Deployment/:Build 事件 |
| 历史/决策 | 为什么、上次、之前、历史、当初、决策、变更、原因、改过 | 对应 :Decision/:BugFix 事件 |
| 项目实体名 | 注册表 65 项目名(user-center、doctor-center、warehouse…) | 用注册表精确匹配 user_message, 非子串猜测 |
| 状态/健康 | 状态、健康、日志、告警、挂了、连不上、报错 | 先 sense 看索引状态再决定查询方式 |

**query 构造规则**: 从任务提取 2-4 个具体关键词短语一次查完; 禁止宽泛词("系统/服务/项目"单独查 → 噪音)。

## 3. 豁免信号 — 可不搜(跳过 L1, 甚至跳过 L0)

| # | 豁免条件 | 判定依据 | 动作 |
|---|---|---|---|
| E1 | 纯对话/闲聊/身份/情感 | 无任何项目实体与关键词 | 不查 |
| E2 | 泛知识问题 | 不涉及已注册项目 | 不查 |
| E3 | 纯文件内代码逻辑 | 任务对象 = 方法/类/文件内部, 无跨实体引用(服务名/配置/API 依赖/历史决策) | 只 L0, 不 L1 |
| E4 | 目标信息已在当前上下文 | 用户贴出配置原文 / 本任务刚查过 / 刚 build 过 / 刚部署过 | 不重复查, 直接用 |
| E5 | KG 无相关数据 | sense 返回 `unregistered` 或 `registered_not_indexed` | 跳过 L1/L2, 直接读磁盘; 未注册附候选注册建议 |
| E6 | L1 空结果 | search_kg 返回 0 命中(正常语义, 非故障) | 停止搜索, 转向磁盘/代码; 不重试同 query |
| E7 | 记忆写入任务 | 触发词"记住/记一下" | 0 搜索, 直接 dt_memorize |
| E8 | 写操作后同主题 | 刚执行 dt_memorize/dt_build/jcli_build, 任务后续同主题 | 缓存已失效, 以操作结果为准, 不重查 |

**豁免不是免检**: E3/E4 豁免的是 L1, L0 仍按类型表执行(除非 E1/E2/E7)。

## 4. 禁止信号 — 禁止搜

| # | 禁止项 | 原因 | 替代动作 |
|---|---|---|---|
| F1 | 每轮 pre_llm_call 裸查 sense/search | token 爆炸(hook 注入的应是 1-2 行缓存摘要, 不是裸查) | 只注入状态摘要, LLM 按需调工具 |
| F2 | 同 session 同 query 重复查(缓存 60s 内) | 浪费 1.4s + 2.2K tokens | 用缓存结果 |
| F3 | degraded 状态反复重试同查询(冷却 30s) | 防雪崩 | 走降级阶梯(磁盘/全文索引), 每任务开头最多重试 1 次 |
| F4 | 预算外追加搜索(L1 ≥3 次 / L2 ≥3 次) | 检索上瘾, 拒绝承认"KG 没有" | 显式说明理由后转磁盘, 不再查 |
| F5 | 敏感字段自动注入/回显 | auth_password 等凭据降噪 | 需用时 elementId 白名单精确查询, 不回显日志 |
| F6 | 宽泛词查询 | 噪音命中稀释可信度 | 2-4 个具体短语 |
| F7 | 跨项目任务中采信未过滤的检索结果 | 实测跨项目噪音(user-center 命中 doctor-center) | 按 project 字段过滤, hop≥1 只当线索 |

## 5. 搜索优先级与工具选择

**顺序固定: L0 → L1 → L2, 逐层下沉、每层有界。** 无跳层默认(先 sense 永远先于 search_kg)。

| 场景 | 工具 | 优先级 | 说明 |
|---|---|---|---|
| 任务开头(默认) | `dt_sense` | L0 | 一条命令: 项目定位 + 索引三态 + 简报; 每次任务 1 次(缓存 120s) |
| 模糊描述/不知确切命名/需语义召回 | `dt_search_kg(query, limit=5)` | L1 首选 | GraphRAG 混合检索, 免写 Cypher; hop=0 当事实, hop≥1 只当线索 |
| 已知精确命名 + 需属性级字段 | `dt search` world 选层 + project 限定, 或 Cypher `MATCH ... WHERE n.name CONTAINS` | L2(可跳过 L1) | 服务名/配置名/域名明确时直达; 显式 RETURN 字段白名单, 不 `RETURN n`; 本环境无全文索引语法 |
| 拿到 elementId 后取完整属性 | memgraph `run_cypher_query` | L2 | 白名单: auth_user/hostname/port/url/service_type |
| 跨项目/全局 | `dt_search --world` 或按项目循环 | L1 变体 | 结果必须带 project 标注 |

**跳过 L1 直达 L2 的条件(全部满足才跳)**: ① 已知确切命名(服务名/配置名/域名); ② sense 显示已索引; ③ 需求是精确属性而非语义关联。其余一律先 L1。

**sense 三态决定后续**:
- `indexed` → L1/L2 可行
- `registered_not_indexed` / `unregistered` → **跳过 L1/L2**, 磁盘直查 + 未注册附候选注册建议(不假装 KG 有数据)
- `degraded: [...]` → 降级阶梯, 上下文标 `⚠ KG degraded`, 不阻塞任务

## 6. 次数边界与失败停止条件

### 每任务搜索预算(硬上限)

| 层 | 上限 | 触发规则 |
|---|---|---|
| L0 sense | 1 次 | 缓存 120s, session 内共享 |
| L1 search_kg | 2 次 | 第 1 次主查; 第 2 次仅当命中差时换词/扩 limit 至 8; 第 3 次起触发 F4 |
| L2 Cypher | 2 次 | 全文索引 1 次 + elementId 取属性 1 次 |
| 总计 | ≤5 次/任务 | 注入 token 总量 ≤3.5K |

### 失败停止条件(三分语义 + 停止线)

| 失败形态 | 判定 | 动作 | 是否重试 |
|---|---|---|---|
| 超时 | MCP 报错或 >10s 心理超时 | 视为降级, 走降级阶梯 | 否(冷却 30s) |
| 连接失败/后端缺失 | sense 返回 degraded 列表 + stats 全 0 | 回退磁盘/本地侦察, 上下文标 `⚠ KG degraded`; 恢复后 dt_learn 补记 | 每任务开头最多 1 次 |
| 空结果 | search_kg 0 命中 | = "KG 确实无此数据"(正常语义), 转向磁盘/代码 | 否 |
| 连续 2 次 L1 无有效命中 | 命中全为 hop≥1 线索或无关项目 | 停止 L1, 转 L2 或直接磁盘 | 否 |

**降级阶梯(查询层)**: Memgraph 活但 Qdrant 挂 → memgraph MCP 全文索引; MCP 层挂 → CLI `dt search` 直连; 全挂 → 直接读磁盘(配置文件/README/部署脚本), 跳过 KG。

**写降级**: KG 不可达时 dt_memorize/dt_build 失败 → 不静默, 明示"知识图谱不可达, 本次决策未记录", 恢复后 dt_learn 批量补记。

## 7. 决策流程(agent 执行序)

```
1. 分类任务类型 (A-H)。E/F/G → 不查, 直接处理。
2. L0: dt_sense(命中项目路径或 cwd) — 除 E1/E2/E7 外必做。
   ├─ degraded → 标 ⚠, 走降级阶梯, 不阻塞
   ├─ 未注册/未索引 → 跳过 L1/L2, 磁盘直查 + 候选注册建议
   └─ indexed → 继续
3. 查触发信号表: 命中 → L1 search_kg(2-4 短语, limit=5)。
   未命中 → 豁免检查(E3 纯代码 / E4 上下文已有) → 豁免则跳过 L1。
4. L1 结果:
   ├─ 0 命中 → 停止搜索, 磁盘/代码
   ├─ 命中差(hop≥1 为主/无关项目) → 第 2 次换词或扩 limit=8; 仍差 → 转 L2 或磁盘
   └─ 有效命中 → 用; 需精确属性 → L2 elementId 白名单
5. 已知精确命名且已索引 → 可直接 L2 全文索引(跳过 L1)。
6. 任何失败 → 三分语义判定, 按停止线执行, 不阻塞任务主流程。
```

## 8. 压缩版决策清单(≤30 行, 可直接写入 SOUL.md / hook 注入)

```markdown
## 知识图谱(KG)查询决策 — digital-twin
1. 原则: KG 是加速器非依赖; 先感知再深入; 数据状态可辨识; 禁止降级伪装; KG 故障不阻塞任务。
2. L0 dt_sense: 每任务开头必查 1 次(先于代码探索)。豁免: 纯对话/记忆写入/无项目上下文。
3. L1 dt_search_kg(q,limit=5): 任务含 服务/配置/凭据/部署/历史决策/项目名/状态 关键词时必查, 否则不查。
4. L2 Cypher: 仅 L1 命中不足或需精确属性时; 已知确切命名+已索引可跳过 L1 直查全文索引 infra_search。
5. 顺序固定 L0→L1→L2; 未索引/未注册项目跳过 L1, 直接读磁盘+附候选注册建议。
6. 任务分类: 配置排查/项目信息询问→L1 必查; 部署操作→L1 建议 1 次; 代码修复→L1 仅涉跨实体引用时。
7. 泛知识问答/闲聊/记忆写入/纯文件内代码逻辑→不查(豁免)。
8. 触发必搜词: 服务名·配置·账号·密码·token·host·端口·域名·部署·发布·回滚·重启·构建·为什么·上次·历史·决策·项目名。
9. 豁免不搜: 信息已在当前上下文(刚查过/用户贴出)/KG 无数据(sense 未索引或 L1 空结果)。
10. 禁止: 每轮 hook 裸查; 同 query 60s 内重复; degraded 反复重试(冷却 30s); 敏感凭据自动注入/回显。
11. hop 规则: hop=0 当事实, hop≥1 只当线索; 跨项目噪音按 project 字段过滤; 宽泛词禁止查询。
12. 边界: 每任务 L0≤1 次, L1≤2 次, L2≤2 次; 总注入 ≤3.5K tokens; 超预算追加须说明理由。
13. 失败即停: 超时 10s→降级回退磁盘+标⚠; 空结果=KG 无此数据不重试; 连续 2 次 L1 无命中→转 L2 或磁盘。
14. 缓存: sense(project,cwd)120s / search(project,q)60s; dt_memorize/dt_build/jcli_build 后失效; 跨会话不缓存。
```
