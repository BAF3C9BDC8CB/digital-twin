# KG 搜索决策规则:何时必搜 / 可不搜 / 禁止搜 (2026-08-11)

设计文档(完整方案): `docs/superpowers/specs/2026-08-11-kg-search-decision-rules.md`。
配套 `references/kg-query-strategy.md`(三层漏斗+token 预算)。本文是 agent 可逐条判定的触发/豁免/禁止规则摘要。原 AGENTS.md 仅一条豁免("无上下文才不查")不可执行, 本体系给出分类矩阵+信号表+硬预算。

## 任务类型 → 搜索要求
| 类型 | L0 sense | L1 search_kg | L2 Cypher | 边界 |
|---|---|---|---|---|
| A 配置/凭据/基础设施排查 | 必查 | **必查** | 按需(elementId 白名单) | L1≤2 L2≤2 |
| B 部署/运维操作 | 必查 | 建议1次(确认操作对象) | 按需 | L1≤1 L2≤1 |
| C 代码修复/开发 | 必查(防改错项目) | 条件必查(涉跨实体引用) | 否 | L1≤1 |
| D 信息询问(项目相关) | 必查 | **必查** | 按需 | L1≤2 |
| E 泛知识问答 / F 纯对话 / G 记忆写入 | 否 | 否 | 否 | 0 |
| H 跨项目/全局对比 | 必查 | 必查(--world) | 按需 | L1≤2 |

分类模糊时取更严格一侧。**豁免的是 L1 不是 L0**——除 E/F/G 外 L0 仍执行, 防漏感知。

## 触发信号(命中必搜 L1)
服务/基础设施名、配置/凭据(token/host/端口/域名/环境名)、部署/生命周期(部署/发布/回滚/构建/jenkins)、历史决策(为什么/上次/历史/变更/原因)、注册表项目名(精确匹配 user_message, 非子串猜测)、状态健康词(状态/日志/告警/挂了)。query=2-4 个具体短语一次查完, 禁宽泛词("系统/服务/项目"→噪音)。

## 豁免信号(可不搜)
纯对话/泛知识/记忆写入(E/F/G); 纯文件内代码逻辑(无跨实体引用); 信息已在当前上下文(刚查过/用户贴出/刚 build 过); **KG 无数据**——sense 未索引/未注册→跳过 L1 直接磁盘+候选注册建议; L1 空结果=正常语义(KG 确实无数据), 停止不重试。

## 禁止信号
每轮 pre_llm_call 裸查 sense/search(hook 只注入缓存摘要); 同 query 60s 内重复; degraded 反复重试(冷却 30s, 每任务开头最多重试 1 次); L1≥3/L2≥3 预算外追加(须显式说明理由); 敏感凭据自动注入/回显(auth_password 等); 宽泛词查询; 未按 project 字段过滤的跨项目结果(实测 user-center 命中 doctor-center)。

## 优先级与跳层
顺序固定 L0→L1→L2, 无跳层默认(先 sense 永远先于 search_kg)。**跳过 L1 直达 L2 需同时满足**: ①已知确切命名(服务名/配置名/域名) ②sense 已索引 ③需求是精确属性。⚠️ L2 用 **MATCH 属性查询**(如 `MATCH (c:Class {name:'GroupService'}) WHERE c.project='im-center'`), 勿用全文索引 `infra_search`/`db.index.fulltext.queryNodes`——那是 Neo4j 语法且本环境索引不存在(2026-08-12 实测, 见 `references/kg-query-strategy.md`), 显式 RETURN 白名单不 `RETURN n`。sense 三态决定后续: indexed→L1 可行; 未注册/未索引→磁盘直查; degraded→降级阶梯+上下文标 `⚠ KG degraded`。

## 边界与失败停止
每任务 L0≤1 / L1≤2 / L2≤2 / 总计≤5 次, 注入 ≤3.5K tokens。失败三分语义: 超时(10s 心理超时)→视为降级不重试; degraded→回退磁盘+恢复后 dt_learn 补记(不静默); 空结果=KG 无此数据; 连续 2 次 L1 无有效命中→转 L2 或磁盘。**KG 故障绝不阻塞任务主流程**。
